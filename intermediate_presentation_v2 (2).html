Motivation

Two forces, one strategic gap

🏛️
Regulatory driver
FIDA / Open Finance
EU consent-based data sharing — delayed, weakened, outcome uncertain.
🤖
Market driver
Rise of AI agents & MCP
Agents create a de-facto need for standardized financial-data interfaces — regardless of FIDA.
Lead
Set standards early, win the first ecosystem partnerships, shape the agent interface.
Do the minimum
Comply and protect — expose the least data, sacrifice external optionality.
Close off
Resist opening, optimize internally — risk losing the customer interface.

The gap: DB has a decade-proven external API program, but how to position it for an AI-agent data economy — and which business models it unlocks — is still open. Doing nothing cedes the customer to uncontrolled screen-scraping.

Research Question

What we set out to answer

Main research question
How can Deutsche Bank leverage its established API program to build sustainable business models in an AI-agent-driven data economy — with or without FIDA?
RQ1 · Interfaces
What role do AI-agent interfaces (APIs & MCP) play in governed financial-data access?
RQ2 · Value
Which data & services create defensible value once open data is commoditized?
RQ3 · Positioning
Should DB lead, do the minimum, or close off — and how do AI agents shift that calculus?

Methodology

Multi-method qualitative design

Document analysis · comparative case studies · business model validation

📚Document & Content Analysis
Method: Qualitative content analysis on regulatory, industry and DB-internal documents

Sources:
  • EC FIDA proposal & impact assessment
  • EBA / ECB open finance reports
  • Oliver Wyman, McKinsey, BCG reports
  • Berlin Group API standards
  • Tink, Plaid, TrueLayer documentation
  • MCP announcements: Anthropic, OpenAI, Visa, Mastercard

Output: Thematic framework for use-case categorisation
🔬Comparative Case Studies
Method: Yin (2018) embedded case study design — 4 cases, cross-case pattern matching

Cases:
  • Plaid + Perplexity Finance
  • LSEG + OpenAI / Claude
  • BBVA + OpenAI
  • UK Open Banking / OBIE partner model

Focus questions:
  • How are MCP servers adopted and discovered?
  • Which channel architectures work?
  • Where are aggregators needed?
  • How are AI partnerships structured?

Output: Pattern-matched findings on channel design
🧭BM Canvas Validation
Method: Osterwalder & Pigneur (2010) canvas + Teece (2010) platform BM theory

Process:
  • Draft canvas per use case from document analysis + case findings
  • Score against viability matrix:
  • Strategic value to DB
  • Regulatory compliance cost
  • Technical feasibility / FIDA readiness
  • Stakeholder review with DB API program

Use-case tiers:
Open data → Partner ecosystem → Proprietary

Output: Validated BM canvas per use case + scoring

First Results

Findings so far & related work

Preliminary findings
DB is already beyond PSD2
Premium APIs for German SMEs without a BaFin licence; wealth-management & SME interfaces live. The open question is strategic, not technical.
Revenue is mostly indirect
Check24 → more account openings; investment-ordering APIs → direct revenue; distribution partners speed acquisition. Direct API prices are minimal.
Data distribution is the bottleneck
Mainframe batch vs. real-time online-banking data; only partial unified data model; a central data layer is still being built.
Related work & sources
Open Finance literature & whitepapers
Industry Open Finance whitepapers (Overview, AI, FinTech, Infrastructure, Insurance, Strategy); academic Open Banking research on APIs & data ecosystems.
Market evidence of agent interfaces
Plaid × Perplexity/OpenAI; LSEG × OpenAI; PayPal agentic commerce — third parties are already becoming the financial interface.
Competitor scan (in progress)
EU front-runners — Dutch banks, Revolut — benchmarked on API offering, strategy & realized use cases.
